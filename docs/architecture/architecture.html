四、两个核心 Harness 流程
FLOW 1 任务规划、执行与结束
intent_recognized
用户输入 → LLM 根据 skill metadata 识别意图
task_planned
多意图 → write_todos 规划 task_list，按表达顺序排列
slots_extracted
加载 skill reference → 按业务规则提槽 → 缺槽追问
workflow_call_started
槽位齐全 → 调用 workflow_api_call → SSE 返回结果
completion_gate_triggered
CompletionGate 终止循环 → completion_state=1
task_completed
前端调用 /completion → completion_state=2 → 卸载 skill → 下一个任务
FLOW 2 Skill 加载、执行与卸载
skill_metadata_injected
首次调用：注入所有 skill 的 name/description/intent_codes 摘要
intent_recognized
LLM 基于元数据识别意图 → 输出 intent_code
skill_loaded
检测到 intent_code → 加载对应 SKILL.md body（意图边界详情）
skill_reference_loaded
加载 reference 文件：slot_filling.md（提槽规则）+ workflow_request.md（API 调用方式）
slots_extracted → workflow_call
LLM 按 reference 规则提槽 → 调用 workflow → 返回结果
skill_unloaded
任务完成后卸载 skill 上下文 → 释放 token 空间 → 切换到下一个 skill
核心衔接：两个流程通过 SkillLifecycleMiddleware 和 CompletionGateMiddleware 严格衔接。 任务流中每个 task 的执行都伴随对应 skill 的加载→执行→卸载周期。前端 /completion 接口是两个流程的交汇点。

规范 Skill 目录结构

阶段加载内容触发时机
Stage 1 name + description + intent_codes

Stage 2 SKILL.md body + ALL references

七、会话隔离与并发控制
SESSION SessionManager
  • 📌 按 (custID, sessionId) 创建隔离 session
  • 📌 映射到 deepagent 的 thread_id = custID:sessionId
  • 🔒 同 session 并发锁 — 同一时刻只允许一个 agent run
  • ⏰ 空闲超时过期 — 默认 30 分钟，到期后重建
  • 👤 用户绑定 — custID 必须匹配
  • 🔄 锁释放后可复用 — 支持多轮对话

九、设计原则
不修改 SDK

deepagent SDK 作为纯依赖使用。Harness 只通过 middleware、tools、skills 参数对接，零侵入。

业务零硬编码

所有业务逻辑（意图码、槽位、API 语义）全部在 skill 文件中声明。框架代码只做扫描/加载/卸载/校验。

渐进式加载

按需加载命中的 skill + reference，未命中的不加载。任务完成后立即卸载，避免上下文膨胀。

前端确认完成

Agent 不能自行标记任务完成。workflow 执行后 CompletionGate 终止循环，由前端 /completion 接口触发最终状态。

多用户 Session 隔离

每个 (custID, sessionId) 有独立的 agent thread、并发锁和生命周期。不同用户完全隔离。

先 Reference 再提槽

Skill reference 文件必须在 LLM 提槽之前注入上下文。保证提槽遵循业务规则，而不是 LLM 自由发挥。
